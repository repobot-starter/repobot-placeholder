# Local Development

## Fresh clone to running app

```bash
npm install          # one install, all workspaces
npm run dev:up       # env bootstrap -> db -> migrate -> codegen -> emulator -> web
```

Then open http://127.0.0.1:5173 and click "Continue as local dev user". `dev:up` is idempotent — rerun it any time; running components are left alone.

## The pieces (all via root npm scripts — never run docker/emulators by hand)

| Command                                           | What it does                                                              |
| ------------------------------------------------- | ------------------------------------------------------------------------- |
| `npm run dev:up`                                  | Everything, in order, with health waits                                   |
| `npm run dev:status`                              | Up/down per component with ports and log paths                            |
| `npm run dev:logs`                                | Tail all service logs                                                     |
| `npm run dev:down`                                | Stop everything (data kept)                                               |
| `npm run dev:db` / `dev:db:test` / `dev:db:reset` | Postgres 16 on :5432 / :5433 (Docker; `DB_MODE=embedded` for Docker-free) |
| `npm run migrate` / `migrate:test`                | Apply SQL migrations                                                      |
| `npm run codegen`                                 | Regenerate after `.gql` / `.proto` changes                                |
| `npm run check:all`                               | Full quality gate (CI-equivalent)                                         |
| `npm test`                                        | Backend blackbox tests (needs test db + migrate:test)                     |
| `npm run storybook`                               | Design-system workbench on :6006                                          |

## Template Studio: preview and iterate on packs

With the dev server running, open http://127.0.0.1:5173/__studio — a gallery of every template pack, grouped **Web** / **Web apps** / **Games**. Clicking a pack activates it with full published-template fidelity (`packs/active.json`, the pack's theme and landing overlays, and — for packs shipping their own `repobot.project.json` — the IA scaffold), and the preview hot-swaps in place. Edit the pack's files as usual; HMR updates the preview.

- `npm run dev:pack -- <key>` is the CLI equivalent (same engine: `scripts/lib/pack-switch.mjs`); `npm run dev:pack` lists packs.
- Switching packs (or resetting to `blank`) restores every overlaid file byte-for-byte — no git diff to clean up. The one exception: stub pages generated by the IA scaffolder are never auto-deleted; the studio and CLI list them, and `git clean -f` removes them.
- Full-stack packs (badge in the sidebar) need the backend: `npm run dev:up`. Client-only packs preview with just the web dev server.

## Where things run

- Web dev server: http://127.0.0.1:5173
- GraphQL (functions emulator): http://127.0.0.1:5001/demo-repobot-base/us-central1/graphql__request__api
- Postgres core/test: 127.0.0.1:5432 / 5433
- Logs: `.dev/logs/`, pids: `.dev/pids/`

## Running alongside the platform stack

The repobot platform's local stack (`dev:local:up` in that repo) owns the
functions emulator port 5001. To run this kernel's stack on the same machine,
move its emulator:

```bash
FUNCTIONS_PORT=5601 npm run dev:up
```

`dev-up.sh` generates `firebase.local.json` (gitignored) with the port
override and points the web server's `VITE_GRAPHQL_URL` at it — nothing to
hand-edit, and the web port already auto-bumps past the platform's (5173 →
5174). Set `FUNCTIONS_PORT` before the first `dev:up` (or `dev:down` first);
an already-running web server keeps the URL it started with.

## Troubleshooting

- `npm run dev:status` first. Each script fails with an actionable message (e.g. Docker not running → start it or `DB_MODE=embedded`).
- Blown-away generated types → `npm run codegen`.
- Weird db state → `npm run dev:db:reset` then `npm run migrate`.
